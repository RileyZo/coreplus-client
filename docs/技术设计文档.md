# 课表查看软件 技术设计文档

## 1. 概述

一款 Android 课表查看应用。从学校后端拉取整学期课表，缓存到本地，按周查看，支持表格/列表布局切换。课程时间根据可切换的作息时间表实时计算。技术栈：Kotlin + Compose + Material3，Ktor Client（OkHttp 引擎），Hilt。

核心约束：

- 后端课表接口请求昂贵（学校 API 有严格请求数量与时间限制），因此**缓存不过期**，理想状态下一学期只请求一次。
- 后端只提供当前学期数据，不区分学期。
- 不允许缓存账号密码；token 有效期约 1 小时，不缓存。
- 刷新需重新登录，并整体覆盖缓存（允许部分成功）。

---

## 2. 数据模型

### 2.1 课程条目（后端返回）

后端 `GET /schedule`（登录后）直接返回整学期数据，周数由返回数组长度决定。每条课程条目包含：

| 字段 | 说明 |
|---|---|
| 课程名 | |
| 学分 | |
| 特性 | 必修等 |
| 上课位置 | 教室 |
| 周数 | 该课所在周（如第 1 周） |
| 星期几 | 星期一… |
| 大节数 | 第几大节 |

数据层**显式存大节**：每条记录绑定“周数 + 星期几 + 大节 + 小节”。

> 实现注记：在后端接口中，“周数”已提升到周层级（`weeks[].weekNumber`），课程条目内不再重复携带；“小节”也不入库，而是由当前作息表中大节的划分实时推导。详见 [API.md](./API.md) §4.3。

### 2.2 周课表

以周为单位组织：`周数 → 该周课程列表`。整学期即多周集合，周数取自接口返回数组长度。

### 2.3 作息时间表

固定结构，始终只有两套（夏季、冬季），用户只能修改内部小节的起止时间。

- 小节列表：每项含小节编号（如 `1-1`、`1-2`）、开始时间、结束时间。
- 大节显式定义，包含其小节划分。
- 大节起止时间 = 该大节首小节开始时间 → 末小节结束时间。
- 内置两套默认值，提供“恢复默认”。

### 2.4 四小节连课的处理

数据层当作两节独立大节处理（如第 1 大节 + 第 2 大节）。仅在 **UI 层**检测同一天连续大节属于同一门课时，视觉上合并为一个块。判断“同一门课”依据三个字段：**课程名称、上课教室、教师**。

## 3. 缓存策略

- **存储形式**：JSON 序列化（kotlinx.serialization），文件放在应用内部存储（`filesDir`）。
- **缓存内容**：当前学期整份课表，以周为单位组织。无需额外元数据（拉取时间、来源账号等）。
- **过期策略**：不过期、不失效。首次获取后，整个学期直接使用缓存。
- **缓存存在性**决定首屏：
  - 无缓存 → 引导登录并拉取。
  - 有缓存 → 直接展示课表。
- **刷新**：需重新登录，整体覆盖。
- **部分成功**：只覆盖成功拉取周的缓存，失败周保留原缓存；既无成功刷新也无缓存的周显示空白。下次刷新直接覆盖。

本地对课程的编辑（查看/编辑/删除）**直接覆盖缓存**，刷新后会丢失。这是可接受的取舍——临时调课不会反映到学校系统，用户应以实际通知为准。

---

## 4. 时间计算

- 不缓存计算结果，**根据当前作息表实时计算**。
- 展示的时间为**整个大节的起止时间**（首小节开始 → 末小节结束），不区分课间。
- 切换作息表后立即重算。

---

## 5. 架构分层

```
UI (Compose)
  ↑
ViewModel (持有当前周次、作息表选择、暴露 ScheduleUiState)
  ↑
Repository (按周取数据：先查缓存，命中返回；未命中请求后端并写入)
  ↑
缓存数据源 (JSON 文件读写)   网络数据源 (Ktor + OkHttp)
```

- **Repository**：负责“取整学期数据”，先查本地 JSON 缓存，命中则返回；未命中则请求后端并写入。暴露“是否有缓存”供首屏判断。
- **ViewModel**：持有当前周次、作息表选择，暴露 UI 状态；周次切换、作息表切换、刷新等交互在此协调。
- **UI**：根据“课程列表 + 当前作息表”实时计算时间并渲染。
- 缓存存在性判断放在 Repository，ViewModel 据此决定进引导页还是课表页。

## 6. UI 设计

### 6.1 布局切换

用户可在**表格**和**列表**之间切换。先实现表格，列表预留抽象。

预留方式：

- `ScheduleLayout` 枚举（Table / List）。
- UI 层根据枚举选择不同 Composable 实现，共享同一个 `ScheduleUiState`。

### 6.2 表格布局

- 二维网格：星期几 × 节次。
- 行头：关键时间线处显示时间；两根时间线中间显示节次编号（1-1、1-2、2-1…）。
- 课程块显示：课程名称、教师、上课地点。空间不够时按**从后往前**顺序隐藏为 `…`。
- 点击课程块可查看 / 编辑 / 删除。
- 四小节连课在视觉上合并为一个块。

### 6.3 周切换

- 顶部提供周次选择器（左右箭头 + 当前周数）。
- 显示“今天是第几周”并自动定位。
- 切换到未缓存的周时，显示上周课程并提示用户。

### 6.4 作息表切换

- 入口放在**顶部**。
- 两套作息表分别对应夏季、冬季。
- 用户可修改起止时间，提供“恢复默认”。

---

## 7. 依赖注入（Hilt）

以下均做成**单例**注入：

- Repository
- 缓存数据源（JSON 文件读写）
- 作息表数据源

当前作息表的选择需**持久化存储**，重启后恢复。

## 8. 技术选型

| 项 | 选择 |
|---|---|
| UI | Kotlin + Compose + Material3 |
| HTTP | Ktor Client（OkHttp 引擎） |
| DI | Hilt |
| JSON | kotlinx.serialization |
| 缓存 | 内部存储 JSON 文件 |

登录流程（表单提交、token 提取）为后端对接细节，完整契约见 **[API.md](./API.md)**：登录成功后拿到 token，立即拉取整学期课表；token 不缓存，刷新时重新登录。

学校教务系统是两段式的（先取验证码图片、再连同账号密码一起提交），因此后端必须代为持有学校会话，token 即该会话的句柄。验证码由后端透传学校的图片，`captchaId` 一次性有效。
